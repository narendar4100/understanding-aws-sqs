Core model

Learn the evaluation order before memorizing service names

An explicit deny wins everywhere. Permission boundaries, service control policies, and session policies never grant access; they only limit it. In the same account, an identity policy or a resource policy can allow a call. Across accounts, both sides normally must allow it. A role also needs a trust policy before anyone can assume it.

Fragile design

One admin key shared by every Lambda

  • • A long-lived access key is baked into the deployment package.
  • • Billing and shipping can delete each other's data because they share AdministratorAccess.
  • • A leaked key remains valid until a person remembers to disable it.

Exam-ready design

One role per workload, scoped to its ARNs

  • • Lambda assumes a role and receives temporary credentials from STS.
  • • The accept role can write one S3 prefix and put one EventBridge event.
  • • The billing role can read receipts and consume one queue. It cannot assume the shipping role.

Operations

Use roles for compute and short-lived credentials for people

Workforce

Federation or IAM Identity Center gives temporary console access. Do not create an IAM user per employee when a central identity provider exists.

Compute

EC2, Lambda, and ECS use roles. An instance profile is how an EC2 instance receives its role.

Partners

Give a partner a role to assume. Require an external ID so the partner cannot be tricked into acting on the wrong account.

Evidence

CloudTrail records the IAM calls. Access Analyzer finds policies that grant broader access than intended.

Limits and exam traps

What IAM will not do for you

  • • IAM does not sign in the customers of your application. That is Amazon Cognito or your own identity provider.
  • • A permission boundary or SCP with Allow does not give that permission to a user.
  • • Groups cannot contain other groups or roles. A Lambda function cannot be placed in an IAM group.
  • • IAM does not encrypt the object. KMS and the service encryption setting do that.
  • • Deleting a user does not delete the resources that user created.

Cost

Users, groups, roles, and policies have no IAM charge

  • • Standard IAM identities and policies are not a separate bill line.
  • • You still pay for the services the principal calls, for KMS requests, and for CloudTrail data events you retain.
  • • Identity Center and external identity products can have their own pricing.

Example: five Lambda roles and twenty scoped policies add no IAM identity charge. The bill appears when those roles call S3, SQS, KMS, or CloudWatch. Confirm the current IAM pricing page before treating any related identity product as free.

Exam drills

Decide before you reveal the answer

Original study decisions for Cloud Practitioner, Solutions Architect Associate, Developer Associate, and SysOps. They are not official exam items.

A role has s3:GetObject Allow and s3:* Deny. Can it read an object?

Deny. An explicit deny overrides the allow.

An SCP allows s3:PutObject. The user has no identity policy. Can the user write?

Deny. An SCP does not grant. The user still needs an allowing identity or resource policy.

Lambda should read one bucket. The team wants an access key in an environment variable. What do you choose?

An execution role with s3:GetObject on that bucket ARN. The function receives temporary credentials.

Account B must read a bucket in account A. The bucket policy allows the role, but the role has no S3 allow. What happens?

Deny. Cross-account access needs an allow on both the identity policy and the resource policy, and no explicit deny.

A permission boundary includes only S3. An administrator attaches EC2 full access. Can the role start an instance?

No. The boundary is the maximum. EC2 actions are outside it, so they are denied.
