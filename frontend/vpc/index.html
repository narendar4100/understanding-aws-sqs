Amazon Virtual Private Cloud

A private network only goes where its routes and firewalls agree

A VPC is your network boundary in a Region. Subnets place workloads in Availability Zones. Route tables decide the next hop, security groups remember the connection, and network ACLs do not.

Core model

Draw the packet path before you add a service

Public means a route to an internet gateway and a public IP, not a subnet named public. Private outbound internet access needs a NAT gateway in a public subnet. S3 and DynamoDB can skip NAT through a gateway endpoint. SQS, SNS, EventBridge, and most other services need an interface endpoint or another path.

Fragile design

Private workers with a route to nowhere

  • • Lambda is attached to a private subnet and then expected to call public AWS APIs.
  • • The route table has only the local VPC route.
  • • A NAT gateway is placed in the private subnet, so it has no path to the internet either.

Exam-ready design

Public entry, private work, cheapest AWS path

  • • Only the load balancer or API edge is public.
  • • Workers use private subnets in at least two Availability Zones.
  • • S3 uses a gateway endpoint. Other APIs use interface endpoints only when they must stay off the internet.

Use the cheapest path that meets the trust boundary

Internet gateway

Inbound and outbound for resources with a public address. One internet gateway attaches to one VPC.

NAT gateway

Outbound only. Put it in a public subnet and point the private default route at it. It charges per hour and per gigabyte.

Gateway endpoint

S3 and DynamoDB. Add the prefix-list route. There is no hourly endpoint charge.

What a VPC will not do for you

  • • It does not give private subnets internet access automatically.
  • • VPC peering is not transitive.
  • • A security group does not create a route.
  • • A gateway endpoint does not serve SQS, SNS, Lambda, or EventBridge.
  • • Putting a workload in a VPC does not encrypt its data.

Well-Architected checks

  • • Security: narrow security groups, private admin paths, and VPC Flow Logs.
  • • Reliability: subnets in more than one AZ.
  • • Cost: a gateway endpoint instead of NAT when the destination is S3.
  • • Performance and sustainability: keep AWS API traffic on the AWS network.

Exam drills

A subnet is named private, but its default route is an internet gateway and the instance has a public IP. Is it private?

No. The route and public address make it internet-reachable if the firewalls allow it.

A NACL allows inbound 443 and denies everything else. Clients hang. Why?

NACLs are stateless. Return traffic uses ephemeral ports and needs an outbound allow.

Only one side of a peering connection has a route. Does the ping work?

No. Peering needs a route on both sides, plus security group or NACL permission.

A private instance must read S3, and the company refuses NAT. What do you add?

A gateway VPC endpoint for S3 and a route for the S3 prefix list.

VPC A peers with B, and B peers with C. Can A reach C through B?

No. Peering is not transitive. Use Transit Gateway or peer A to C.
