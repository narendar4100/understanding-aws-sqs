One business event, seven services, three consumers

The accept function writes orders/<orderId>.json to a private bucket and publishes OrderPlaced. A fraud rule matches amounts of 1000 or more and targets the fraud queue directly. A second rule matches every order and targets an SNS topic. Billing subscribes with no filter. Shipping subscribes only when itemType is physical. Each queue has its own DLQ.

Fragile design

The API does every job

  • • The customer waits for fraud, payment, and shipping.
  • • A shipping outage loses the order because no receipt was stored.
  • • One admin role can delete every bucket.

Exam-ready design

Accept, store, publish, then buffer

  • • The accept role can write one prefix and put one event.
  • • EventBridge selects the route. SNS fans out. SQS lets a team go offline.
  • • Workers use private subnets and an S3 gateway endpoint. No NAT gateway is required for S3.

What Northline will not promise

  • • It does not make a card charge exactly once. Billing must record the order id first.
  • • Shipping does not roll back because billing failed. The teams compensate.
  • • The bus does not retain a backlog. The queues do.
  • • A filter is not authorization. Shipping must still reject an unexpected message.

The multiplier is consumers

Ten million orders create ten million custom EventBridge events and twenty million SQS deliveries from two SNS subscriptions, plus fraud deliveries for the high-value subset. A NAT gateway left running will dominate that bill. This lab does not create one.

Well-Architected checks

  • • Security: separate roles, a private bucket, and no public queue policy.
  • • Reliability: one DLQ per queue, an archive on the bus, and idempotent billing.
  • • Performance: the API returns at publish time. Consumers scale on queue depth.
  • • Cost: an S3 gateway endpoint, and no idle NAT gateway.

Exam drills

Digital order, amount 40. Which queues receive it?

Billing only. Fraud does not match. Shipping is filtered out.

Shipping deletes the message and then crashes. What brings it back?

Nothing in SQS. Delete only after the work is durable, and make replay idempotent.

Workers move into a private subnet and cannot read receipts. What is the smallest fix?

An S3 gateway endpoint and its prefix-list route. Do not start with NAT.

Billing charges twice after a timeout. Where is the defect?

The consumer applied the side effect before recording the order id. The queue delivered at least once.
