Amazon Simple Storage Service

A private object store with a class for each access pattern

S3 stores objects in buckets. You choose a storage class for access frequency, retrieval speed, and whether the object can live in one Availability Zone. Security is a bucket and IAM boundary, not a folder permission.

Separate durability, availability, and access frequency

S3 Standard is designed for eleven nines of durability across Availability Zones. Current S3 provides strong read-after-write consistency for create, overwrite, delete, and list. Block Public Access can override a bucket policy that would otherwise make an object public.

Fragile design

A public bucket used as an application disk

  • • A bucket policy allows everyone to read receipts.
  • • Seven-year records stay in S3 Standard.
  • • The application lists the whole bucket to find one order.

Exam-ready design

Private objects, explicit keys, and a lifecycle

  • • Block Public Access stays on. Callers use IAM or a short-lived presigned URL.
  • • Hot receipts use Standard. Cold records transition to a Glacier class.
  • • The application stores the object key and gets that key directly.

Block Public Access

Account or bucket settings can block a public policy even if someone adds one later.

Versioning

Required for replication. A delete can become a delete marker.

Object Lock

Governance can be overridden by a special permission. Compliance cannot be shortened, even by root, until retention ends.

Encryption

SSE-S3, SSE-KMS, or a customer-provided key. A presigned URL still obeys the signer.

Best lab: class first, then public access

Use a hot product image, an unknown-access log, a seven-year contract, and a rebuildable thumbnail. Then ask what happens when a public bucket policy meets Block Public Access. Students should reject One Zone-IA for the only copy of a contract and reject a public bucket for receipts.

What S3 will not do for you

  • • S3 is not a POSIX file system or a relational database. Prefixes are key names.
  • • Objects do not change class unless Intelligent-Tiering or a lifecycle rule is configured.
  • • The S3 website endpoint does not provide HTTPS. Use CloudFront when browsers need TLS.
  • • A presigned URL cannot exceed the signer's permission and remains valid until expiry.
  • • Replication requires versioning and does not copy existing objects unless you request it.

Storage, requests, retrieval, and transfer are separate

Example: a 200 KB receipt read thousands of times per day belongs in Standard or Intelligent-Tiering. Glacier Flexible Retrieval would add retrieval delay and fees. Minimum storage duration on IA and Glacier classes can also erase the expected saving. Confirm current S3 pricing.

Well-Architected checks

  • • Security: Block Public Access, least privilege, encryption, and access logs.
  • • Reliability: versioning and multi-AZ classes for primary data.
  • • Cost: lifecycle matches the real retrieval pattern. Abort incomplete multipart uploads.
  • • Performance: multipart upload and direct key access. Do not list the bucket per request.

Exam drills

A bucket policy allows public GetObject, and Block Public Access is on. Can an anonymous user read?

No. Block Public Access wins over that public policy.

The only copy of a contract must survive an AZ loss. Which cheaper class is unacceptable?

S3 One Zone-IA. It stores data in one Availability Zone.

The team wants HTTPS on the S3 website endpoint. What do you add?

CloudFront, or another HTTPS endpoint. The S3 website endpoint does not terminate HTTPS.

Replication is configured, but versioning is off. What is missing?

Versioning on both the source and destination.

An object is overwritten and immediately read. What consistency applies?

Strong consistency. The reader sees the latest overwrite or delete.
